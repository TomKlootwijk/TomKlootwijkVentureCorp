The earlier package over-weighted chemical and biological language. This report replaces that reading. Chemical, biological, optical, artistic, political, and hardware passages are retained only where they instantiate, motivate, or test the shared operator vocabulary.

The decisive source rule

Do not judge the archive as a proposal about rasterization, raymarching, voxel storage, or a conventional frame loop. Those are downstream projection tools. The authoritative object is an ontology of directly queryable relations, events, phases, identities, and transitions. [S1 p. 1]

Executive synthesis

1. Executive correction and findings

The corrected reading is not "hidden chemistry." It is a cross-domain corpus attempting to describe a common computational substrate beneath geometry, sensing, graphics, simulation, identity, memory, and optional photonic hardware. Its strongest form is a spherical-support event calculus: a finite grammar generates a continuous state manifold; local radial-angular supports select relevance; compatibility determines whether co-located sectors can interact; explicit relation surfaces define events; typed transitions update state while preserving invariants and lineage; images are optional outputs. [S1 pp. 1, 5-7]

01

Core object

A state manifold and relation algebra, not a framebuffer, mesh inventory, or global voxel grid.

02

Topological role

Sheets, parity, gluing, overlap, and pinch points organize coupling and transition semantics.

03

Graphics role

Raster, ray, vector, display, and print pipelines are materialized views downstream of a query result.

04

Information role

Grammar, exogenous log, lineage, branch, address, and compatibility form a compact data architecture.

05

Prototype role

Equation World Zero tests six headless queries over a deliberately restricted relation family.

06

Hardware role

Hollowlens-0 is an optional bounded optofluidic implementation, not proof of the whole ontology.

What survives the full corpus

  • Retain: direct state/event queries, local spherical supports, relation guards, compatibility, phase sheets, lineage, explicit transitions, and novelty-aware logging.
  • Translate: double vacuum into uncoupled sectors; hourglass into routing; Klein bottle into an explicit gluing/orientation map; matrix-in-glass into a calibrated transfer matrix.
  • Demote: claims that a geometric metaphor automatically supplies physical law, computational complexity, security, medical control, or perfect hardware behavior.
  • Reject: universal O(1), zero memory, zero latency, zero heat, literal topological immunity, and direct biological control as established consequences.
Bounded feasibility verdict

The corpus is internally coherent and prototype-worthy when restricted to controlled relation families, headless state/event queries, explicit compatibility, finite grammar depth, and testable lineage. As a universal replacement for graphics, simulation, memory, cognition, and semantics at once, it remains unproven. [S1 pp. 1, 7-12]

Part II

Formal architecture of the spherical-support event calculus

The corpus becomes technically legible when its operators are typed as state, relation, support, compatibility, event, transition, identity, and projection.

Ontology before projection

5. The query-first core

The central inversion is a change in the question asked by the system. A conventional scene pipeline asks what geometry is stored, what must update this frame, and how a sensor produces an image. The equation-world asks which finite relations generate possible states, what state holds at a requested time, which event occurs next, and which sectors are allowed to couple. That is a shift from picture production to direct state semantics. [S1 pp. 9-10]

Projection-first question

  • Which surfaces and samples exist now?
  • How are they projected this frame?
  • Which pixels or rays are evaluated?
  • How is temporal state replayed?

Query-first question

  • Which relations define the admissible state?
  • What is q_e(t) at requested time t?
  • What is the earliest compatible guard crossing?
  • Which identity and invariant survive the transition?

This does not ban graphics. It relocates graphics. A projection may be raster, ray-based, vector, volumetric, print, sensor, or photonic. None of those output forms is allowed to overwrite the authority of the state manifold.

A world state is more than position

6. State product and entity identity

The mature formal condensation treats state as a product space. Position is only one coordinate family. Time, phase, sheet, lineage address, and branch are independent dimensions of the computational state. This is the formal reason that co-location does not force interaction and that identity does not collapse into a current coordinate. [S1 pp. 5-6]

Normalized product state space
Q = P^n x R_time x S^1_phase x Z2_sheet x A_address x B_branch
Entity state used in this report; p_e is a narrow parity/route bit
q_e(t) = (x_e(t), t, phi_e(t), sigma_e(t), a_e, b_e, p_e)

World description

Source formal core plus explicit exogenous log
W = (G, R, T, I), with an external novelty log L
  • G: finite grammar or generative program.
  • R: relation and guard family.
  • T: typed transition rules.
  • I: invariants that must survive designated transitions.
  • L: exogenous log for shocks, interventions, or novelty not implied by the closed grammar.

Identity

The corpus repeatedly insists that identity is not exhausted by a snapshot. The normalized information-science form is a lineage address derived from seed, grammar path, and invariant history. The hash form below is a prototype representation, not a source-mandated cryptographic standard.

Identity invariant

Person(t) != Snapshot(t) is best read as an architectural caution: current position, role, image, or record is a projection of identity, not the full identity. [S5 pp. 6-9]

The event is a three-gate conjunction

7. Relation, support, compatibility, event, transition

A pure geometric intersection is insufficient. The source formal core requires three conditions: the relation or guard reaches its event surface; the state lies within a declared local support; and the compatibility predicate admits coupling. Only then is the transition invoked. [S1 pp. 5-7; S6 pp. 3, 5, 7]

Relation or guard surface
R_j(q; theta_j) = 0
Local spherical, conic, shell, causal, or policy support
C_alpha(q,t) <= 0
Compatibility predicate
chi(e,j,t,context) in {0,1}
Earliest admitted event
t* = min { t >= t0 : R_j(q_e(t)) = 0 AND C_alpha(q_e(t),t) <= 0 AND chi(e,j,t) = 1 }
Typed transition
q_e(t*+) = T_j(q_e(t*-), context)

Why SDF zero matters

Earlier passages sometimes imagine "going past zero" in a continuous field as if that alone escaped rasterization. The mature synthesis corrects this: the zero set is not a magical continuation surface. It is the explicit locus where event semantics are invoked. The engine solves for a root or certified interval and then applies a transition. If it merely samples the field again and again, hidden marching has returned. [S1 p. 7; S2 pp. 16-19; S3 pp. 30-33]

Typed event record

Event {
  event_id, entity_id, relation_id, transition_id,

  guard_crossed, root_multiplicity, confidence,
  pre_state_hash, post_state_hash,

The event record makes the architecture auditable. A result is not merely "a hit"; it carries the support, predicate version, guard, uncertainty, lineage, and transition outcome that justified it.

Same coordinate, different sector

8. Double vacuum as relational exclusion

Double vacuum is the most successful cross-domain operator in the corpus. Its mature meaning is not a second or stronger emptiness. It means that two states may share a spatial coordinate while remaining unavailable to one another because their phase, sheet, orientation, lineage address, mode, time window, or policy is incompatible. The second "vacuum" is the absence of coupling. [S1 p. 6; S5 pp. 32-33]

Core axiom
x_A = x_B does not imply can_couple(A,B)
Normalized predicate
can_couple(A,B,context) = chi(sheet, phase, address, mode, time, policy)

Information architecture reading

  • Namespace separation: identical keys or coordinates can exist under different sheet or branch contexts.
  • Access control: compatibility is a declared join and permission predicate.
  • Counterfactual isolation: branches can share a base state without contaminating one another.
  • Mode isolation: in the bounded photonic translation, uncoupled optical modes or channels instantiate the same principle.
Not a physical shield

Double vacuum does not establish literal immunity, ghost-like passage, bodily control, or a new vacuum law. Those literalized claims are excluded. In hardware, the bounded translation is uncoupled or deliberately isolated modes and channels. [S6 pp. 2, 10]

Transition topology without topological miracle

9. Hourglass, parity, pinch, and gluing

The quad hourglass condenses four recurring motifs: a four-sector partition, a central pinch or rank-changing event locus, a vertical invariant axis, and a swept phase-controlled coupling arc. In the mature reading, it is a routing visualization and transition table. It is not by itself a proof of non-orientable physics. [S1 p. 6; S2 pp. 23-25]

One-bit parity

The bit has a narrow role. It may encode route A/B, orientation parity, admitted/rejected, fresh/stale, or available/unavailable, but only under a declared schema. The bit never contains the optical amplitude, full geometry, uncertainty, lineage, policy, and branch state. [S1 pp. 5-6; S6 p. 7]

Possible transition-side parity toggle
p_after = NOT p_before

Klein bottle and Mobius language

A Klein-bottle or Mobius motif is retained only as an orientation or gluing abstraction. To become executable, it needs explicit ports, an orientation map, a quotient or identification rule, and a transfer function. Without those objects, the topology remains metaphor. The bounded hardware report makes this discipline explicit. [S6 pp. 2, 5, 10]

Operationally retained

  • sheet identification
  • orientation flip
  • route parity
  • port-to-port gluing
  • branch transition

Not automatically supplied

  • physical containment
  • zero tunneling
  • constant complexity
  • security or bodily immunity
  • electromagnetic or fluid law

Store novelty, not every projection

11. Memory, lineage, branches, and event sourcing

The corpus proposes that closed dynamics need not be stored frame by frame. A seed and finite grammar regenerate predictable structure; an exogenous log stores only irreducible novelty; branch history and lineage store the information needed to reconstruct splits, merges, and interventions. The mature report treats this as a bounded hypothesis, not a zero-memory theorem. [S1 pp. 7-8; S5 pp. 10-11]

Bounded novelty-proportional memory hypothesis
M_required ~= seed + grammar + exogenous_log + necessary_branch_history

What can be regenerated

  • Closed trajectories defined by fixed expressions.
  • Implicit geometry defined by finite coefficients.
  • Deterministic transitions whose inputs and branch context are known.
  • Derived images, meshes, and reports as materialized views.

What still accumulates

  • External interventions and sensor surprises.
  • Ambiguous or non-deterministic branch choices.
  • Predicate and schema revisions.
  • Identity split/merge reconciliation.
  • Numerical certificates, uncertainty, and calibration state.

This is an event-sourced design pattern: state may be recomputed from compact generative structure plus an authoritative log. The advantage exists only when replay, solving, and branch resolution remain cheaper than storing or materializing the avoided structure. [S1 p. 8]

Reference execution plan

function NEXT_EVENT(entity e, time t0, relation_family J):
    candidates = []
    for relation j in J:
        if not policy_can_apply(e, j): continue
        roots = certified_roots(R_j(q_e(t)) = 0, t >= t0)
        for r in roots:
            state = state_at(e, r)
            if support_contains(C_j, state) and chi(e, j, r) == 1:
                candidates.append(certified_event(j, r, state))
    return earliest_ordered(candidates)

function APPLY_TRANSITION(event ev):
    verify guard, predicate version, confidence, and pre-state hash
    post = T_ev(pre_state, context)
    verify invariants
    append event and lineage edges
    return post

Query planner obligations

  • Choose a restricted relation family with known or certified root methods.
  • Use support and compatibility to prune before expensive solving.
  • Return intervals or uncertainty when a unique exact root is not certified.
  • Make branch precedence and event ordering explicit.
  • Never treat absence of a found root as proof of absence without solver bounds.
Part IV

Computer graphics and sensing boundary

The corpus overlaps deeply with graphics, but its mature claim is query-versus-projection, not sphere-versus-grid.

The projector is not the state space

13. Computer graphics boundary

Rasterization, raymarching, and ray tracing answer projection and transport questions. The proposed substrate answers state, event, compatibility, identity, and reachability questions. The two layers overlap because implicit geometry, cones, local charts, and visibility can feed images. They remain distinct because the image is an output of a query, not the ontological store. [S1 pp. 9-10]

SystemPrimary questionOverlap with the corpusWhy it is not the core
RasterizationHow do stored surfaces project into pixels now?Can emit a view from queried geometry/state.Pixels and frames are not authoritative world state.
RaymarchingWhat does repeated field sampling along a projected direction reveal?Uses SDFs and directional queries.Repeated sampling is explicitly not the mature event-solving core.
Ray tracingWhich transport/visibility paths connect endpoints?Cones and supports may define candidate paths.The core cone also represents causal, semantic, collision, memory, and grammar support.

The correct comparison is therefore not "spherical graphics versus Cartesian graphics." It is "query semantics versus projection semantics." Local polar or spherical charts may improve a sensor or output adapter without requiring global remeshing of the state model.

From implicit query result to screen or print

14. KC Vector as a downstream projection adapter

The KC Vector document is most useful as a projection-layer case study. It starts with a local log-polar address, evaluates implicit SDF/CSG boundaries, accumulates phase and amplitude near an edge, and quantizes the result for display or print. This is compatible with the mature corpus only when KC output is treated as a view over the query substrate, not as the substrate itself. [S7 pp. 1-10]

Projection stages

Local log-polar address transform from S7
rho = ln(sqrt(x^2 + y^2)), theta = atan2(y,x)
Source SDF/CSG operators
union = min(f1,f2), intersection = max(f1,f2), subtraction = max(f1,-f2)
Report-level normalization of phase-amplitude accumulation
A(p) = sum_k a_k exp(i * phi_k)
  1. Query result: obtain an implicit boundary or relation slice from the authoritative substrate.
  2. Local address: map the output domain to log-polar coordinates where radial scaling becomes translation in rho.
  3. Boundary evaluation: evaluate SDF/CSG and its gradient near the requested contour.
  4. Phase-amplitude accumulation: combine local edge contributions. This is the disciplined replacement for the source's under-specified "Feynman vector" term.
  5. Quantization: choose a screen, vector, or print policy.

Screen and print paths

  • Screen: 1-bit pulse-density modulation and anisotropic dithering distribute tone temporally and spatially.
  • Vector: contour extraction preserves analytic edges for scalable output.
  • Print: CMYK mapping, log-polar blue-noise screening, SDF edge locking, and dot-gain compensation create a static 1-bit prepress representation.
Projection-layer caveat

These display and prepress mechanisms do not prove that the world model is 1-bit, log-polar, or quantum. They show how a rich query result can be emitted through a highly constrained output channel.

Sensor diversity without global remeshing

15. Apertures, sieves, jitter, and local charts

The optical/perceptual source contributes a productive analogy: every sensor is a local transfer function with an aperture, field of view, angular/radial support, spectral response, sampling mosaic, and uncertainty. The source uses microscopes, camera obscura, compound eyes, retinal mosaics, whiskers, sonar, UV response, and artistic inversion to explore that idea. The mature architecture keeps the local support and filter, not the literal equivalence of all sensors. [S3 pp. 1-20, 24-33]

Sieve

A sieve can mean a physical receptor mosaic, a spatial index, a mode filter, a support predicate, or a quantization grid. The report therefore requires a layer tag whenever the term is used. "Bypass the sieve" can mean avoiding unnecessary materialization or broad-phase scanning, but it cannot mean that all filtering disappears. Compatibility and support are themselves filters.

Jitter

Jitter is retained as a controlled sampling or dithering operator. It can shift an aperture, sensor, or quantization pattern to fill blind spots, estimate uncertainty, or decorrelate aliasing. It does not restore a mathematically continuous world from finite samples without an error model.

Layer-specific jitter model
q_sample(t) = q_nominal(t) + epsilon(t), with declared spectrum and bound

Local spherical chart

The strongest spherical claim is local: a sensor, coupler, agent, or query has radial reach, angular support, orientation, shell structure, and uncertainty. The world may remain hybrid. This avoids both raster-everything and polar-everything. [S1 pp. 1, 6; S6 p. 3]

Prototype, measurement, and research discipline

Restricted, headless, falsifiable

Equation World Zero is the corpus's proper first experiment.   • Annular-sector local support.
  • Sheet, phase, and invariant-tag compatibility.
  • Typed transition with optional sheet change, parity toggle, branch creation, and state update.

The included Python prototype demonstrates closed-form state_at, analytic line/circle event roots, compatibility rejection for co-located sheets, parity routing, lineage update, and an auditable event record. 19. Optional physical bridge: Hollowlens-0

The physical path is optional and should not be confused with the software ontology. S6 translates the corpus into a conventional optofluidic experiment: a local spherical input field, a tunable liquid coupler, a 2x2 interferometric waveguide, balanced detectors, and a digital sidecar that applies support, compatibility, guard, confidence, parity, and lineage logic. [S6 pp. 1-9]

Type-separated stack

  • Maxwell layer: optical field in the actual dielectric geometry.
  • Liquid/interface layer: meniscus curvature, refractive index, actuation, settling, hysteresis.
  • Guided-mode layer: attenuation, propagation constants, coupling, phase, interference.
  • Event layer: support, compatibility, measured guard, threshold, uncertainty, lineage.
  • Control sidecar: calibration, drift detection, policy, timing, fallback reference.

Spherical throughput

Verified events per second
Theta_sph = N_verified / Delta_t

A verified event counts only if it was inside the declared support, compatible with the selected channel, crossed the measured guard, and met the confidence threshold. Photon flux, baud rate, or propagation speed alone is not spherical throughput. [S6 p. 6]

Minimum comparison

The system-level claim remains unproven until the complete source, liquid actuator, waveguide, detector, calibration loop, and B.C.E. sidecar deliver more verified events per second and per joule than a matched electronic baseline at the same error and uncertainty boundary. [S6 pp. 9, 12]

22. Research program and recommended next build

The source corpus closes with the right instruction: formalize Equation World Zero, and begin with state, compatibility, event, transition, identity, and memory. The proof target is narrow: one nontrivial relation family that answers state-at-time and next-event without replaying every frame, under explicit compatibility, with stable lineage, bounded expression growth, and memory proportional to novelty rather than geometric extent. [S1 p. 12]

Recommended build order

  1. Freeze schemas. Adopt the included state and event JSON schemas; version every compatibility predicate.
  2. Choose one relation family. Begin with line/circle/quadratic guards or another family with certified roots.
  3. Implement six queries. Keep the core headless and deterministic.
  4. Instrument every cost. Candidate counts, root work, branch growth, memory, error, and event ordering.
  5. Add one projection adapter. Use KC Vector as a downstream view, never as the world store.
  6. Stress topology semantics. Test co-location, parity, sheet gluing, splits, merges, and invariant preservation.
  7. Compare against a baseline. Frame stepping, spatial index, or event queue at equal correctness.
  8. Only then consider Hollowlens-0. Pre-register support, mode, guard, error, energy, and calibration boundaries.
Exit criterion

Proceed only if compatibility plus event solving and lineage maintenance cost less than the state/materialization work avoided, at the same correctness and uncertainty boundary. Otherwise retain the useful operators inside a conventional hybrid engine.
